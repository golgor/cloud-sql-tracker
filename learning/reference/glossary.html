Quick Reference

Glossary

Authoritative definitions for every domain term, system concept, and infrastructure pattern used throughout cloud-sql-tracker and this textbook.

Every concept in this codebase maps to an exact vocabulary defined in CONTEXT.md. Using precise names prevents architectural drift between the CLI control plane, systemd, the desktop bar widget, and background proxy processes.

ADC (Application Default Credentials)

Google Cloud's standard credential discovery strategy. Client libraries and the cloud-sql-proxy binary search for credentials in a defined order: first checking the GOOGLE_APPLICATION_CREDENTIALS environment variable, and falling back to a default JSON file at ~/.config/gcloud/application_default_credentials.json (generated via gcloud auth application-default login). In cloud-sql-tracker, ADC is a hard operational prerequisite (ADR 0002); the control plane verifies local credential presence without initiating network calls or token exchanges.

Codebase: src/env/mod.rs (AdcStatus, adc_check), src/commands/doctor.rs.

Avoid: "gcloud login" (which authenticates the gcloud CLI, not necessarily ADC libraries), service account keys embedded in config.

cgroup (Control Group)

A Linux kernel feature that isolates, prioritizes, and accounts for resource usage across a tree of processes. Systemd places each transient service unit inside its own dedicated cgroup. When cloud-sql-tracker configures KillMode=control-group, stopping a unit signals every process inside that cgroup (including helper subprocesses spawned by wrapper scripts), preventing leaked background orphans.

Codebase: src/supervisor.rs (transient unit properties: KillMode=control-group).

Connection

A configured target Cloud SQL instance paired with a unique, non-default local listen endpoint. Identified by a unique slug (such as fe-dev or backend-prod), containing an instance connection string (project:region:instance), a fixed port (e.g. 15432), a group tag, and optional flags like private_ip or auto_iam_authn.

Codebase: src/model.rs (struct Connection), src/config.rs.

Avoid: Service, database (which refers to the remote engine), tunnel.

Control plane

The short-lived, stateless command-line tool (cloud-sql-tracker) that starts, stops, observes, and reports on Google Cloud SQL Auth Proxy instances. The control plane manages metadata and lifecycle, but never handles database traffic, TCP proxying, or encryption itself.

Codebase: src/main.rs, src/cli.rs, src/commands.rs.

Avoid: Daemon (cloud-sql-tracker exits immediately after executing a command), agent, wrapper script.

D-Bus

The standard Linux inter-process communication (IPC) message bus system. It allows desktop programs and CLI tools to invoke methods and query properties on running services. cloud-sql-tracker talks to systemd's user manager over the session/user bus at the well-known destination org.freedesktop.systemd1 using the pure-Rust zbus crate, avoiding shell-outs to systemctl or systemd-run.

Codebase: src/supervisor.rs (zbus::blocking::Connection, D-Bus method calls like StartTransientUnit and StopUnit).

Foreign process

Any process listening on a Connection's designated local TCP port that does not belong to this control plane's managed systemd unit. This includes unmanaged manual invocations of cloud-sql-proxy, local Docker Compose containers, PostgreSQL servers, or stray background scripts. Reconcile classifies these as port conflicts (HealthState::Error with ErrorCode::PortInUse).

Codebase: src/reconcile.rs, src/port.rs (listener attribution via procfs).

Avoid: Orphan (cloud-sql-tracker does not adopt unmanaged processes), stranger.

Golden example

A reference sample document stored in the repository (e.g. examples/status.v1.json, examples/connections.json, examples/doctor.v1.json) that represents a valid, canonical output or input. Every contract change requires updating the prose document, the JSON schema, and the golden example together in the same pull request.

Codebase: examples/*.json, scripts/validate-contracts.sh.

Group

A logical string label attached to Connections in configuration (such as fe, backend, or iot). Groups allow bulk lifecycle operations in the CLI (e.g. cloud-sql-tracker start --group backend) and category-level aggregation in UI widgets.

Codebase: src/model.rs, src/config.rs, src/commands/select.rs.

Avoid: Environment, project (the GCP project is part of the instance connection string).

Health state

The operational state of a Connection at a single moment in time, produced by Reconcile. Exactly one of four states: stopped (no unit running, port closed), starting (unit activating or newly active within the 10-second start window), running (unit active and listening on the configured port), or error (crashed, timed out, port conflict, or execution failure).

Codebase: src/model.rs (enum HealthState), src/reconcile.rs.

Avoid: Status (ambiguous with the entire Status document), phase.

Layer 1 (Contract verification)

Static schema validation executed in CI and pre-push hooks. Validates that all repository golden example files (examples/*.json) strictly conform to their corresponding JSON schemas (schemas/*.json) using check-jsonschema.

Codebase: scripts/validate-contracts.sh, .github/workflows/ci.yml.

Layer 2 (Contract verification)

Integration testing of the compiled binary. Tests spawn the built executable (cloud-sql-tracker status --json, doctor --json) and validate its real stdout output directly against the JSON schema definitions using the in-process jsonschema crate.

Codebase: tests/cli_json_contracts.rs.

MSRV (Minimum Supported Rust Version)

The oldest version of the Rust compiler guaranteed to compile the project. cloud-sql-tracker pins MSRV (currently 1.97.1) across three files in strict synchronization: Cargo.toml (rust-version), mise.toml (tools.rust), and .github/workflows/ci.yml (env.RUST_VERSION).

Codebase: Cargo.toml, mise.toml, .github/workflows/ci.yml.

procfs

The Linux virtual filesystem mounted at /proc that presents kernel and process data structures as file hierarchies. Used by the port adapter (via the Rust procfs crate) to inspect /proc/net/tcp for listening sockets and /proc/<pid>/fd/ to attribute open socket file descriptors to owning PIDs and process names (/proc/<pid>/comm).

Codebase: src/port.rs.

Proxy process

An operating system process running Google's official cloud-sql-proxy executable, dedicated to handling traffic for exactly one Connection under a transient systemd service unit.

Codebase: src/supervisor.rs (proxy_argv), src/env/mod.rs.

Avoid: Daemon, tracker process.

Reconcile

The pure, read-only decision engine that maps a Connection's configuration identity and observed runtime signals (systemd unit state, start time, TCP probe liveness, socket listener PID) to a definitive Health state and error classification. Reconcile performs zero I/O, does not read clocks directly, and never adopts foreign processes.

Codebase: src/reconcile.rs (pub(crate) fn reconcile), docs/reconcile.v1.md.

Avoid: Desired-state loop, controller, reconciliation daemon, auto-heal engine.

Source

A field in the Status document indicating whether a Connection's reported Health state is backed by an active, managed systemd unit (unit) or by no managed process (none).

Codebase: src/model.rs (enum Source), src/reconcile.rs.

Avoid: Origin, provider, parent, orphan.

Status document

The versioned JSON document emitted on stdout when running cloud-sql-tracker status --json. Contains root metadata (version: 1, cli_version, generated_at), an array of per-Connection status objects, and summary state tallies for UI consumption.

Codebase: src/model.rs (struct StatusDocument), src/commands/status.rs, docs/status-document.v1.md.

Avoid: State file (the control plane stores no state on disk), report, ping response.

Supervisor

The Linux user-level service manager (systemd --user) acting as the durable parent process for all proxy instances. The supervisor manages process execution, automatic SIGTERM shutdown, cgroup isolation, and journal logging.

Codebase: src/supervisor.rs, docs/research/supervisor-io.md.

Avoid: Our CLI (the CLI is short-lived; systemd is the supervisor).

Transient unit

A systemd service unit created dynamically in memory via the D-Bus method StartTransientUnit (named cloud-sql-proxy-<id>.service). Transient units do not require unit files on disk in ~/.config/systemd/user/ and are cleaned up automatically when stopped.

Codebase: src/supervisor.rs (start_transient), docs/research/systemd-user-units.md.

Unit

The transient systemd user service instance (cloud-sql-proxy-<id>.service) created and supervised by systemd --user to run a single proxy process.

Codebase: src/model.rs (struct UnitName), src/supervisor.rs.

Avoid: Service (alone), background job.

User bus

The per-user D-Bus session bus instance established at graphical login or via systemd lingering. Accessible via the socket at $XDG_RUNTIME_DIR/bus, enabling unprivileged user tools to interact with user-level services and managers.

Codebase: src/supervisor.rs (zbus::blocking::Connection::user()).

XDG config path

The standard directory for user-specific configuration files per the XDG Base Directory Specification. cloud-sql-tracker defaults to $XDG_CONFIG_HOME/cloud-sql-tracker/connections.json (falling back to ~/.config/cloud-sql-tracker/connections.json).

Codebase: src/config.rs (default_path()).

Source: CONTEXT.md and repository architecture documentation.
