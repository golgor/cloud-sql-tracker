A textbook for the curious reader

cloud-sql-tracker

A guided reading of a small, real Rust codebase: what it does, how it does it, and — mostly — why it is built this way. Twelve short chapters, big picture first, detail last.

What this book assumes

You can read Rust: ownership, Result, enum, match, traits. That is enough.

You are assumed to know nothing about this project, Google Cloud SQL, systemd, D-Bus, or Application Default Credentials. Each of those is explained once, in one sentence, the first time it appears. Terms you will meet repeatedly live in the glossary.

The subject in one paragraph

cloud-sql-tracker is a stateless command-line control plane. It starts, stops, and reports on several of Google's cloud-sql-proxy processes at once — each on a fixed local port — and publishes machine-readable status for scripts and a desktop bar widget. It does not implement the database tunnel itself. Google's binary does that; this tool is the thing that remembers which proxies you wanted, on which ports, and tells you honestly whether they are up.

How to read it

In order, the first time. The book is arranged as a funnel: Part I is orientation you cannot skip without the rest feeling arbitrary, and Part II contains the one algorithm at the heart of the program. Parts III–V can be dipped into later as reference.

Each chapter ends with three recall questions. Answering them from memory, before opening the answer, is what turns reading into knowing — recognising a fact you have just read is a poor test of whether you own it.

Contents

Part I · Orientation

  1. The problem

    Seven databases, one default port, and no way to see what is running. Why this tool exists at all, and what it refuses to do.

  2. The language

    Connection, Proxy process, Unit, Health state, Source. The vocabulary is the design — and these words are the Rust type names.

  3. The shape

    A short-lived CLI, systemd as the process owner, and four hard decisions recorded as ADRs. Why there is no daemon.

Part II · The core

  1. Contracts first

    Prose, JSON Schema, and a golden example — changed together or not at all. The method that shaped every module.

  2. The model and the config

    The types, and the validation that makes a bad config file a hard error instead of a mystery at runtime.

  3. Reconcile: the pure heart

    One observation in, one Health state out. No I/O, no clock, no excuses — and therefore exhaustively testable. The best chapter.

Part III · The edges

  1. Talking to systemd

    D-Bus without the mystique: transient units, typed properties, and why we never shell out to systemctl.

  2. Three smaller adapters

    Probing a port, finding a binary and credentials, reading the journal. Small files, sharp lessons.

Part IV · The layers above

  1. The commands seam

    Everything the tool can do, with no argv parsing and no printing. Batches, idempotence, and two clocks that must not be merged.

  2. The thin shell

    clap in exactly one module, five exit codes, and a hand-rolled --version flag with a good excuse.

Part V · Proof and operations

  1. Proving it works

    Pure-seam unit tests, schema contracts, a real spawned binary, and the human gate no test can replace.

  2. Shipping it

    One toolchain number in three files, a measured release profile, and what actually happens to your proxies at shutdown.

Reference

Written to be printed and kept beside you, not read once.

  1. Glossary

    Every domain and infrastructure term, defined once, with where it appears in the repo.

  2. Cheat sheet

    Subcommands, exit codes, Health states, the module map, key paths, and the release steps in order.

A note on trust

Every code snippet in this book is copied verbatim from the repository and carries the file and line it came from. Where a chapter explains a design decision, it cites the frozen contract in docs/ or the ADR that settled it, because in this project those documents — not anyone's memory — are the authority.

If a snippet and the repository ever disagree, the repository is right and this book has drifted. That is a bug worth reporting.
